## Задание 1. Имена, ссылки и изменяемость
### Эксперимент A. Неизменяемый объект
```
a = 10
b = a

print(a, b)
print(id(a), id(b))

a += 1

print(a, b)
print(id(a), id(b))
```
#### Ожидаемые результаты:
В первой строке `10 10`, во второй строке совпадающие `id` имен `a` и `b`, в третьей строке `11 10`, в четверной строке несовпадающие `id` имен `a` и `b`.
#### Результат:
```
10 10
140732496274840 140732496274840
11 10
140732496274872 140732496274840
```

**Почему после операции a += 1 значение, связанное с именем b, не изменилось?**

После операции `a += 1` значение, связанное с именем `b`, не меняется, так как тип `int` неизменяемый: операция `a += 1` не меняет объект `10`, а создаёт  объект `11` и перепривязывает к нему имя `a`, тогда как имя `b` продолжает указывать на прежний объект `10`.

#### 4. Две схемы связей между именами и объектами: до и после переназначения:
**До переназначения** (`second = first`): два имени, один объект.

```
 имена            объекты
┌───────┐
│ first │──────┐
└───────┘      ᐯ
            ┌─────────────────┐
            │ list [10,20,30] │   id = X
            └─────────────────┘
               ᐱ
┌────────┐     │
│ second │─────┘
└────────┘
```

**После переназначения** (`second = list(first)`): два имени, два объекта.

```
 имена               объекты
┌───────┐      ┌─────────────────┐
│ first │─────>│ list [10,20,30] │   id = X
└───────┘      └─────────────────┘

┌────────┐     ┌─────────────────┐
│ second │────>│ list [10,20,30] │   id = Y  (Y != X)
└────────┘     └─────────────────┘
```

Равенство `first == second` остаётся истинным, но `first is second` уже ложно.
### Практическая задача
Конфигурация: словарь с полями `name` (строка), `members` (список участников) и `launch_params` (вложенный список пар «параметр, значение»).
```
import copy

# 1. Создаём первую конфигурацию
config_1 = {
    "name": "Учебный проект",
    "participants": ["Анна", "Борис", "Виктор"],
    "launch_params": [
        ["режим", "тестовый"],
        ["язык", "русский"]
    ]
}

# 2. Получаем вторую конфигурацию простым присваиванием
config_2 = config_1

print("=== ДО ИЗМЕНЕНИЙ (присваивание) ===")
print("config_1:", config_1)
print("config_2:", config_2)
print("Это один объект?", config_1 is config_2)
print()

# 3. Меняем что-то во второй конфигурации — и смотрим, как это повлияет на первую
config_2["participants"].append("Галина")
config_2["launch_params"][0][1] = "рабочий"

print("=== ПОСЛЕ ИЗМЕНЕНИЙ (через config_2) ===")
print("config_1:", config_1)
print("config_2:", config_2)
print("Это всё ещё один объект?", config_1 is config_2)
print()

# Вывод о нежелательном совместном изменении
print("Вывод: при простом присваивании объекты общие, изменения видны в обеих конфигурациях.")
print()

# 4. Создаём действительно независимую копию конфигурации
config_3 = copy.deepcopy(config_1)

print("=== ДО ИЗМЕНЕНИЙ (deepcopy) ===")
print("config_1:", config_1)
print("config_3:", config_3)
print("Это один объект?", config_1 is config_3)
print()

# Меняем в независимой копии
config_3["participants"].append("Дмитрий")
config_3["launch_params"][1][1] = "английский"

print("=== ПОСЛЕ ИЗМЕНЕНИЙ config_3 ===")
print("config_1:", config_1)
print("config_3:", config_3)
print()

# 5. Подтверждаем независимость с помощью assert
assert config_1 is not config_3
assert config_1["participants"] is not config_3["participants"]
assert config_1["launch_params"] is not config_3["launch_params"]
assert config_1["launch_params"][1] is not config_3["launch_params"][1]
assert config_1["participants"] == ["Анна", "Борис", "Виктор", "Галина"]
assert config_1["launch_params"][1][1] == "русский"
assert config_3["participants"][-1] == "Дмитрий"
assert config_3["launch_params"][1][1] == "английский"
print("assert прошёл: config_3 независима от config_1")
print()

print("=== ИТОГ ===")
print("Общие объекты: config_1 и config_2 (один словарь со всем содержимым).")
print("Независимые объекты: config_3 (deepcopy), включая вложенные списки.")
```

## Вопросы для анализа

**1. Меняет ли присваивание `second = first` сам объект?**
Нет. Присваивание только привязывает имя `second` к уже существующему объекту. Объект не копируется и не изменяется, у него просто появляется второе имя.

**2. Почему операция над неизменяемым объектом приводит к связыванию имени с другим объектом?**
Неизменяемый объект нельзя поменять на месте, поэтому результат операции всегда новый объект (или уже существующий объект с нужным значением). Имя перепривязывается к нему, а старый объект остаётся нетронутым для других имён.

**3. Как определить, что два имени обозначают один объект?**
С помощью оператора `is` (`first is second`) или сравнения `id(first) == id(second)`. Оператор `==` для этого не подходит: он сравнивает значения, и разные объекты могут быть равны.
