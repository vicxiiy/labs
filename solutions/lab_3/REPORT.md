### Часть 1. Проверка диапазонов

Функция возвращает сообщение об ошибке или `None`, если данные корректны:
```
def validate(score: int, absences: int) -> str | None:
    if score < 0 or score > 100:
        return f"результат {score} вне диапазона 0–100"
    elif absences < 0 or absences > 5:
        return f"пропусков {absences} вне диапазона 0–5"
    else:
        return None
```

### Часть 2. Определение уровня результата

Если пропущено более 3 занятий, уровень снижается на одну ступень, но ниже «недостаточного» не опускается:
```
def get_level(score: int, absences: int) -> str:
    if score >= 90:
        index = 3
    elif score >= 75:
        index = 2
    elif score >= 60:
        index = 1
    else:
        index = 0

    if absences > 3 and index > 0:
        index -= 1
    return LEVELS[index]
```

```
def process_record(score: int, work_type: str, absences: int) -> tuple[str, str | None]:

    work = describe_work(work_type)

    return text, level
```

**Порядок проверки условий:**

1. Сначала проверяются диапазоны. В `process_record` первым вызывается `validate`. Если она вернула сообщение об ошибке, функция сразу завершается через `return`: уровень не определяется и тип работы не разбирается.
2. Внутри `validate` сначала проверяется результат, затем количество пропусков. Как только сработало первое условие, остальные не проверяются, поэтому при двух ошибках сразу (сценарий 14) выводится только сообщение о результате.
3. В `get_level` пороги проверяются от большего к меньшему: `>= 90`, затем `>= 75`, затем `>= 60`, иначе — остальное. Поэтому в каждом условии достаточно записать только нижнюю границу: верхняя следует из того, что предыдущие условия не сработали.
4. Снижение уровня на ступень выполняется после определения исходного уровня: условие `absences > 3 and index > 0`. Часть `index > 0` защищает от выхода за нижнюю границу: без неё для `index = 0` получилось бы `LEVELS[-1]`, то есть «отличный».
5. В `describe_work` значение сравнивается по очереди с `exam`, `project`, `practice`, а `case _` обрабатывает всё остальное.

**Недостижимые ветви при выбранном порядке:**

- `get_level`: условия `elif score >= 75` и `elif score >= 60` не выполняются для значений 90 и выше, потому что их уже обработала первая ветвь. Условие `elif score >= 60` не выполняется для значений 75 и выше.
- `get_level`: ветвь `else` достижима только для значений 0–59. Отрицательные значения и значения выше 100 до неё не доходят: они отсечены в `validate`.
- `validate`: ветвь `elif` не выполняется, если ошибочен результат, потому что управление уходит в первую ветвь с `return`. Ветвь `else` достижима только когда обе величины корректны.
- `process_record`: код после проверки `error` (вызовы `get_level` и `describe_work`) недостижим для некорректных данных.
- `describe_work`: ветвь `case _` по условию задачи при корректном вводе недостижима. Она оставлена для неизвестных значений и проверяется сценарием 11 с типом `lab`.

Если изменить порядок в `get_level` на обратный (сначала `score >= 60`), то ветви `score >= 75` и `score >= 90` стали бы недостижимыми, и любой результат от 60 получал бы уровень «удовлетворительный». Поэтому порядок от большего порога к меньшему выбран намеренно.

**Этап 1. Первый проход.** За один проход вычисляем сумму, минимум, максимум и число чётных значений (минимум и максимум начинаются с первого элемента списка):

```
def first_pass(values: list[int]) -> tuple[int, int, int, int]:
    total = 0
    minimum = values[0]
    maximum = values[0]
    even_count = 0
    for value in values:
        total += value
        if value < minimum:
            minimum = value
        if value > maximum:
            maximum = value
        if value % 2 == 0:
            even_count += 1
    return total, minimum, maximum, even_count
```

**Этап 2. Второй проход.** Среднее известно только после первого прохода, поэтому значения, большие среднего, считаются отдельно:

```
def count_above_average(values: list[int], average: float) -> int:
    count = 0
    for value in values:
        if value > average:
            count += 1
```

### Линейный поиск первого вхождения

Функция проходит по списку слева направо и возвращает индекс первого найденного элемента и число выполненных сравнений. Если число отсутствует, возвращается индекс `-1`.

```
def linear_search(items: list[int], target: int) -> tuple[int, int]:
    comparisons = 0
    for index in range(len(items)):
        comparisons += 1
        if items[index] == target:
            return index, comparisons
    return -1, comparisons
```

### Дополнительный алгоритмический эксперимент

Делители перебираются от 2 до корня из `n` включительно. Условие `divisor * divisor <= n` равносильно `divisor <= √n`, при этом вычисления идут только в целых числах, без вещественного корня.
```
def is_prime(n: int) -> bool:
    if n < 2:
        return False
    divisor = 2
    while divisor * divisor <= n:
        if n % divisor == 0:
            return False
        divisor += 1
    return True
```

**Псевдокод проверки простоты:**
```
функция ПРОСТОЕ(n):
    если n < 2: вернуть Ложь
    делитель = 2
    пока делитель * делитель <= n:
        если n делится на делитель без остатка: вернуть Ложь
        делитель = делитель + 1
    вернуть Истина
```

**Почему ограничение делителей квадратным корнем корректно.** Пусть `n` — составное число, то есть `n = a · b`, где `1 < a ≤ b`. Тогда `a · a ≤ a · b = n`, то есть меньший из двух делителей не превосходит √n. Значит, у любого составного числа есть делитель в диапазоне от 2 до √n, и если ни один делитель из этого диапазона не подошёл, число простое. Границу √n необходимо включать: для `n = p²` единственный нетривиальный делитель равен ровно √n (например, для 25 это 5, а для 7921 это 89). Условие `divisor * divisor <= n` включает эту границу и не требует вычисления корня в вещественных числах.

### Практическое расширение

**Сортировка выбором.** Функция сортирует список по возрастанию на месте:
```
def selection_sort(items: list[int]) -> None:
    size = len(items)
    for i in range(size - 1):
        min_index = i
        for j in range(i + 1, size):
            if items[j] < items[min_index]:
                min_index = j
        if min_index != i:
            items[i], items[min_index] = items[min_index], items[i]
```

**Бинарный поиск.** Поиск выполняется в отсортированном списке. Одно сравнение — один шаг цикла: элемент в середине сравнивается с искомым значением (равно / меньше / больше). В линейном поиске одно сравнение — одна проверка равенства элемента с искомым значением.
```
def binary_search(items: list[int], target: int) -> tuple[int, int]:
    low = 0
    high = len(items) - 1
    comparisons = 0
    while low <= high:
        middle = (low + high) // 2
        comparisons += 1
        if items[middle] == target:
            return middle, comparisons
        elif items[middle] < target:
            low = middle + 1
        else:
            high = middle - 1
    return -1, comparisons
```

**Псевдокод бинарного поиска:**
```
функция БИНАРНЫЙ_ПОИСК(отсортированный_список, число):
    слева = 0
    справа = длина списка - 1
    сравнений = 0
    пока слева <= справа:
        середина = (слева + справа) // 2
        сравнений = сравнений + 1
        если список[середина] равен числу: вернуть середина, сравнений
        если список[середина] < числа: слева = середина + 1
        иначе: справа = середина - 1
    вернуть -1, сравнений
```

```
    return [(i * 7919 + 13) % 10007 for i in range(size)]


def run_comparison() -> None:

        selection_sort(data)

            _, binary_count = binary_search(data, target)
            linear_total += linear_count
            binary_total += binary_count

            if binary_count > binary_max:
                binary_max = binary_count

        _, binary_miss = binary_search(data, -1)
        search_rows.append((size, linear_total / size, linear_max, linear_miss,
                            binary_total / size, binary_max, binary_miss))
```

### Оценка сложности алгоритмов

| Алгоритм | Временная сложность | От какого параметра зависит число операций | Дополнительная память |
|---|---|---|---|
| Первый проход `first_pass` | O(n) | От длины списка `n`: каждый элемент обрабатывается ровно один раз, внутри цикла выполняется фиксированное число действий | O(1): `total`, `minimum`, `maximum`, `even_count` |
| Второй проход `count_above_average` | O(n) | От длины списка `n`: каждый элемент сравнивается со средним один раз | O(1): переменная `count` |
| Статистика целиком `analyze` | O(n) + O(1) + O(n) = O(n) | От длины списка `n`: два прохода выполняются друг за другом, а не вложенно | O(1) |
| Линейный поиск `linear_search` | O(n) в худшем случае (элемент последний или отсутствует), O(1) в лучшем (элемент первый) | От длины списка `n` и позиции первого вхождения. Поиск числа 12 даёт 1 сравнение, а числа 100 — 10 | O(1): `index` и `comparisons` |
| Проверка простоты `is_prime` | O(√n) в худшем случае (число простое или квадрат простого), O(1) в лучшем (например, чётное число отбрасывается на первом делителе) | От значения числа `n`: цикл перебирает делители 2, 3, 4, …, пока `divisor * divisor <= n`, то есть не более √n значений | O(1): `n` и `divisor` |
| Сортировка выбором `selection_sort` | O(n²) во всех случаях: внешний цикл идёт `n - 1` раз, внутренний каждый раз просматривает остаток списка, всего `n(n − 1) / 2` сравнений | От длины списка `n`; порядок элементов на число сравнений не влияет | O(1): сортировка на месте, нужны только индексы `i`, `j`, `min_index` |
| Бинарный поиск `binary_search` | O(log n) в худшем случае, O(1) в лучшем (элемент в середине) | От длины списка `n`: на каждом шаге рассматриваемая часть уменьшается вдвое, поэтому шагов не больше `log₂ n + 1`. Требует отсортированного списка | O(1): `low`, `high`, `middle`, `comparisons` |

### Построение структур

Функция `add_submission` добавляет одну запись во все структуры сразу. Построение с нуля — это просто вызов этой функции для каждой записи, поэтому новую запись можно добавить без повторного построения:
```
def add_submission(students, laboratories, attempts_by_student,
                   best_results, attempts_count, students_by_lab, record):
    student, lab, score = record
    key = (student, lab)

    students.add(student)
    laboratories.add(lab)

    if student not in attempts_by_student:
        attempts_by_student[student] = []
    attempts_by_student[student].append((lab, score))

    if key not in best_results or score > best_results[key]:
        best_results[key] = score

    attempts_count[key] = attempts_count.get(key, 0) + 1

    if lab not in students_by_lab:
        students_by_lab[lab] = set()
    students_by_lab[lab].add(student)


def build_structures(records):
    students = set()
    laboratories = set()
    attempts_by_student = {}
    best_results = {}
    attempts_count = {}
    students_by_lab = {}
    for student, lab, score in records:
        add_submission(students, laboratories, attempts_by_student,
                       best_results, attempts_count, students_by_lab,
                       (student, lab, score))
    return (students, laboratories, attempts_by_student,
            best_results, attempts_count, students_by_lab)


(students, laboratories, attempts_by_student,
 best_results, attempts_count, students_by_lab) = build_structures(submissions)
```

Кроме пяти структур из условия, добавлен словарь `students_by_lab` (работа → множество студентов, сдававших её). Он нужен для операций над множествами и для запроса `completed`.

### Объяснения

**Почему множество подходит для хранения уникальных значений?** Множество не хранит повторов: повторное `add` того же значения ничего не меняет. Студент `anna` встречается в записях три раза, но в `students` лежит один раз. Кроме того, проверка «есть ли значение во множестве» и добавление в среднем выполняются за O(1), а для множеств определены операции пересечения (`&`), разности (`-`) и объединения (`|`).

**Почему кортеж можно использовать как ключ словаря?** Ключ словаря должен быть хешируемым: у него есть значение хеша, которое не меняется за время жизни объекта, и его можно сравнивать на равенство. Кортеж неизменяемый, поэтому хеш кортежа `("anna", "lab_01")` вычисляется из хешей его элементов и всегда остаётся одним и тем же.

**Почему список нельзя использовать как ключ словаря?** Список изменяемый. Если бы он был ключом, после `append` его содержимое, а значит и хеш, изменились бы, и словарь не смог бы найти сохранённое значение: оно лежало бы «не там», где его ищут. Поэтому Python запрещает хешировать списки, и такая попытка вызывает `TypeError`.

**Почему словарь предпочтительнее списка для частого поиска по составному ключу?** В списке пришлось бы хранить записи `(студент, работа, результат)` и каждый раз просматривать их все — это O(n). Словарь по хешу ключа `(student, lab)` находит значение в среднем за O(1), независимо от числа записей.

### Оценка сложности операций с коллекциями

| Коллекция | Добавление | Поиск | Замечание |
|---|---|---|---|
| `set` | в среднем O(1) | `in` — в среднем O(1) | в худшем случае (много коллизий хешей) O(n) |
| `dict` | в среднем O(1) | по ключу — в среднем O(1) | в худшем случае O(n); хеш составного ключа считается по его длине (здесь 2 элемента) |
| `list` | `append` — в среднем O(1) (с учётом редких расширений) | по значению — O(n), по индексу — O(1) | в `attempts_by_student` список используется только для хранения попыток по порядку, искать в нём не требуется |
| `tuple` | создаётся один раз | по индексу — O(1) | неизменяемый, поэтому подходит как ключ |

Добавление записи в `add_submission` — это несколько операций со средней сложностью O(1), поэтому вся функция работает за O(1). Построение структур для `n` записей — O(n).

### Практическое расширение. Текстовые запросы

Команда разбирается методом `split()` на части. Первое слово определяет операцию (`match / case`), остальные — аргументы. Для неизвестной команды, неверного числа аргументов и отсутствующего ключа выводится сообщение, программа не завершается аварийно:
```
def execute_query(line: str) -> str:
    parts = line.split()
    if len(parts) == 0:
        return "Пустая команда"

    command = parts[0]
    arguments = parts[1:]

    match command:
        case "student":
            if len(arguments) != 1:
                return "Формат: student <имя>"
            name = arguments[0]
            if name not in attempts_by_student:
                return f"Студент {name} не найден"
            return f"Попытки {name}: {attempts_by_student[name]}"
        case "best":
            if len(arguments) != 2:
                return "Формат: best <имя> <работа>"
            key = (arguments[0], arguments[1])
            if key not in best_results:
```

```
def arithmetic_mean(values: list[float]) -> float:
    """Возвращает среднее арифметическое непустого списка.

    Для пустого списка контракт выполнить нельзя, поэтому возвращается 0.0.
    """
    if len(values) == 0:
        return 0.0
    total = 0
    for value in values:
        total += value
    return total / len(values)


def normalize_name(name: str) -> str:
    """Удаляет лишние пробелы и приводит каждую часть имени к нужному регистру."""
    parts = name.split()
    if len(parts) == 0:
        return ""
    return " ".join(part.capitalize() for part in parts)


def build_report(
    student: str,
    results: list[int],
    *,
    precision: int = 2,
    prefix: str = "Результат",
) -> str:
    """Формирует строковый отчет о результатах студента."""
    clean_name = normalize_name(student)
    if len(results) == 0:
        return f"{prefix} {clean_name}: результатов нет"
    mean_value = arithmetic_mean(results)
    return f"{prefix} {clean_name}: среднее {mean_value:.{precision}f}, работ {len(results)}"


def collect_tags(*tags: str, lowercase: bool = True) -> tuple[str, ...]:
    """Возвращает очищенные теги без пустых значений и повторов."""
    result = []
    for tag in tags:
        clean = tag.strip()
        if lowercase:
            clean = clean.lower()
        if clean == "":
            continue
        if clean not in result:
            result.append(clean)
    return tuple(result)
```

1. **Коллекции не изменяются.** Функции только читают `values`, `results` и `tags`. Новые данные собираются в локальных переменных (`total`, `parts`, `result`).
2. **Ранний `return`.** Если контракт выполнить нельзя (пустой список, пустое имя, нет результатов), функция сразу возвращает безопасное значение и дальше не идёт.
3. **`precision` и `prefix` только именованные.** Они стоят после `*` в сигнатуре `build_report`, поэтому передать их позиционно нельзя.

### Исследование LEGB

```
course = "Основы программирования"


def outer() -> None:
    counter = 0

    def inner() -> None:
        nonlocal counter
        step = 1
        counter += step
        print("inner: step =", step, "| counter =", counter, "| course =", course, "| len('abc') =", len("abc"))

    inner()
    inner()
    print("outer: counter =", counter)
```

**Результат:**
```
inner: step = 1 | counter = 1 | course = Основы программирования | len('abc') = 3
inner: step = 1 | counter = 2 | course = Основы программирования | len('abc') = 3
outer: counter = 2
global: course = Основы программирования
```
`nonlocal counter` позволяет `inner` изменить имя из объемлющей функции `outer`. Глобальное имя `course` не изменяется (проверено через `assert`).

**Схема областей видимости:**
```
┌─ Built-in (B): len, print, ... ─────────────────────────────┐
│  ┌─ Global (G): course, outer ───────────────────────────┐  │
│  │  ┌─ Enclosing (E): функция outer ──────────────────┐  │  │
│  │  │  counter                                        │  │  │
│  │  │  ┌─ Local (L): функция inner ────────────────┐  │  │  │
│  │  │  │  step                                     │  │  │  │
│  │  │  └───────────────────────────────────────────┘  │  │  │
│  │  └─────────────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
Поиск имени идёт изнутри наружу: L → E → G → B
```

**Порядок поиска каждого использованного имени в `inner`:**

| Имя | Где найдено | Как выполнялся поиск |
|---|---|---|
| `step` | L — локальная область `inner` | найдено сразу, так как создано присваиванием внутри `inner` |
| `counter` | E — область `outer` | в `inner` объявлено `nonlocal`, поэтому имя берётся из объемлющей функции, и `counter += step` изменяет именно его |
| `course` | G — глобальная область | нет ни в L, ни в E, найдено на уровне модуля; только читается, без `global` |
| `len`, `print` | B — встроенная область | нет ни в L, ни в E, ни в G, найдены среди встроенных имён |

### Ошибка изменяемого значения по умолчанию

Исходная функция и исправленная:
```
def add_result(value, results=[]):
    results.append(value)
    return results


def add_result_fixed(value, results=None):
    if results is None:
        results = []
    results.append(value)
    return results
```

**Результат:**
```
Исходная версия:
[1]
[1, 2]
[1, 2, 3]
Объект значения по умолчанию: ([1, 2, 3],)
Исправленная версия:
[1]
[2]
[3]
Значение по умолчанию: (None,)
```

**Объяснение через жизненный цикл объекта значения по умолчанию.** Значение по умолчанию вычисляется один раз, в момент выполнения инструкции `def`, а не при каждом вызове. Пустой список `[]` создаётся при определении функции и сохраняется в `add_result.__defaults__`. При вызове без второго аргумента параметр `results` связывается с этим же самым объектом. Так как список изменяемый, `append` меняет его на месте, и изменения накапливаются между вызовами: в выводе видно, что после трёх вызовов в `__defaults__` лежит `[1, 2, 3]`. В исправленной версии по умолчанию хранится неизменяемое `None`, а новый список создаётся внутри функции при каждом вызове, поэтому вызовы независимы.

### Практическое расширение

```
def apply_to_results(operation, values):
    return [operation(value) for value in values]


def add_bonus(score):
    return score + 5


def make_threshold_checker(threshold):
    def check(score):
        return score >= threshold
    return check
```
```
results = [55, 70, 88]
print(apply_to_results(add_bonus, results))
print(apply_to_results(lambda score: score * 2, results))
print("Исходный список:", results)

passed_60 = make_threshold_checker(60)
passed_75 = make_threshold_checker(75)
print(apply_to_results(passed_60, results))
print(apply_to_results(passed_75, results))
print("Значение в замыкании passed_60:", passed_60.__closure__[0].cell_contents)
print("Значение в замыкании passed_75:", passed_75.__closure__[0].cell_contents)
```

**Результат:**
```
[60, 75, 93]
[110, 140, 176]
Исходный список: [55, 70, 88]
[False, True, True]
[False, False, True]
Значение в замыкании passed_60: 60
Значение в замыкании passed_75: 75
```
`apply_to_results` принимает функцию как обычный аргумент: ей можно передать и именованную функцию `add_bonus`, и анонимную `lambda`. Исходный список при этом не меняется, возвращается новый.

**Какое значение сохраняется в замыкании?** Каждый вызов `make_threshold_checker` создаёт свою вложенную функцию `check` и свой набор имён внешней функции. Имя `threshold` остаётся доступным внутри `check` и после завершения `make_threshold_checker`, потому что функция `check` запоминает его в замыкании. У `passed_60` в замыкании лежит 60, у `passed_75` — 75. Эти два значения независимы друг от друга, поэтому одна и та же функция проверки работает с разными порогами.

### Функции

```
def mean(values):
    if len(values) == 0:
        return None
    total = 0
    for value in values:
        total += value
    return total / len(values)


def minimum(values):
    if len(values) == 0:
        return None
    result = values[0]
    for value in values:
        if value < result:
            result = value
    return result


def maximum(values):
    if len(values) == 0:
        return None
    result = values[0]
    for value in values:
        if value > result:
            result = value
    return result


def classify(score):
    if score >= 90:
        return "отличный"
    elif score >= 75:
        return "хороший"
    elif score >= 60:
        return "удовлетворительный"
    else:
        return "недостаточный"


def student_summary(name, results):
    if len(results) == 0:
        return {"name": name, "count": 0, "mean": None, "min": None,
                "max": None, "category": NO_RESULTS}
    average = mean(results)
    return {
        "name": name,
        "count": len(results),
        "mean": average,
        "min": minimum(results),
        "max": maximum(results),
        "category": classify(average),
    }


def find_top_students(students):
    best = None
    leaders = []
    for name, results in students.items():
        average = mean(results)
        if average is None:
            continue
        if best is None or average > best:
            best = average
            leaders = [name]
        elif average == best:
            leaders.append(name)
    return leaders


def group_summary(students):
    categories = {category: 0 for category in CATEGORIES}
    categories[NO_RESULTS] = 0
    total = 0
    count = 0
    for name, results in students.items():
        summary = student_summary(name, results)
        categories[summary["category"]] += 1
        for value in results:
            total += value
            count += 1
    if count == 0:
        group_mean = None
    else:
        group_mean = total / count
    return {
        "students": len(students),
        "results": count,
        "mean": group_mean,
        "categories": categories,
        "leaders": find_top_students(students),
    }
```

### Отчёт

```
def format_number(value):
    if value is None:
        return "—"
    return f"{value:.2f}"


def format_plain(value):
    if value is None:
        return "—"
    return str(value)


def format_report(student_data, group_data):
    lines = ["=== Результаты студентов ==="]
    for item in student_data:
        lines.append(
            f"{item['name']}: работ {item['count']}, среднее {format_number(item['mean'])}, "
            f"мин {format_plain(item['min'])}, макс {format_plain(item['max'])}, "
            f"категория — {item['category']}"
        )

    lines.append("")
    lines.append("=== Рейтинг ===")
    ranked = [item for item in student_data if item["mean"] is not None]
    ranked = sorted(ranked, key=lambda item: item["mean"], reverse=True)
    if len(ranked) == 0:
        lines.append("Рейтинг пуст")
    for place, item in enumerate(ranked, 1):
        lines.append(f"{place}. {item['name']} — {format_number(item['mean'])}")

    lines.append("")
    lines.append("=== Группа ===")
    lines.append(f"Студентов: {group_data['students']}, результатов: {group_data['results']}")
    lines.append(f"Общий средний результат: {format_number(group_data['mean'])}")
    if len(group_data["leaders"]) == 0:
        lines.append("Лидеры: нет")
    else:
        lines.append("Лидеры: " + ", ".join(group_data["leaders"]))
    for category, number in group_data["categories"].items():
        lines.append(f"{category}: {number}")
    return "\n".join(lines)


def analyze_group(students):
    student_data = [student_summary(name, results) for name, results in students.items()]
    group_data = group_summary(students)
    return format_report(student_data, group_data)
```

| 2 | один студент `{"Мария": [80, 90]}` | лидер Мария, среднее 85, категория «хороший» | совпадает | OK |
| 3 | несколько лидеров (Ира и Олег, среднее 85) | лидеры `["Ира", "Олег"]` | совпадает | OK |
| 4 | пустая группа `{}` | 0 студентов, среднее `None`, лидеров нет, «Рейтинг пуст» | совпадает | OK |
| 5 | студент без результатов (Лев) | категория «нет результатов», в среднее и лидеры не входит | совпадает | OK |
| 6 | граничные значения 0, 59, 60, 74, 75, 89, 90, 100 | категории по таблице | совпадают | OK |
| 7 | минимум, максимум, среднее, пустые списки | 2, 9, `None`, `None`, `None`, 1.5 | совпадает | OK |

### Контракты публичных функций

| Функция | Допустимые входные данные | Результат | Особые случаи |
|---|---|---|---|
| `mean(values)` | список чисел | среднее арифметическое (`float`) | пустой список → `None` |
| `minimum(values)` | список чисел | наименьшее значение, найденное без `min()` | пустой список → `None` |
| `maximum(values)` | список чисел | наибольшее значение, найденное без `max()` | пустой список → `None` |
| `classify(score)` | число (обычно 0–100) | одна из строк: «отличный» (≥ 90), «хороший» (≥ 75), «удовлетворительный» (≥ 60), «недостаточный» | границы 60, 75, 90 относятся к высшей из двух категорий |
| `student_summary(name, results)` | имя и список результатов | словарь `name`, `count`, `mean`, `min`, `max`, `category` | пустой список → `count = 0`, остальные числа `None`, категория «нет результатов» |
| `group_summary(students)` | словарь «имя → список результатов» | словарь `students`, `results`, `mean`, `categories`, `leaders` | пустая группа → `mean = None`, `leaders = []`, все счётчики категорий 0 |
| `find_top_students(students)` | словарь «имя → список результатов» | список имён с наибольшим средним (одно или несколько) | студенты без результатов пропускаются; пустая группа → `[]` |
| `format_report(student_data, group_data)` | список итогов студентов и итоги группы | строка отчёта | отсутствующие значения выводятся как «—»; рейтинг пуст, если нет студентов с результатами |

Ни одна из функций не изменяет полученные данные.

### Декомпозиция и сложность

**Декомпозиция.** Программа разделена на три уровня: базовые вычисления (`mean`, `minimum`, `maximum`, `classify`), итоги (`student_summary`, `group_summary`, `find_top_students`) и вывод (`format_report`). Функции вычисления ничего не печатают, а функция вывода ничего не считает. Благодаря этому каждую функцию можно проверить отдельно, а правило для студента без результатов задано в одном месте (в `student_summary` и базовых функциях).

**Сложность построения общей статистики.** Пусть `m` — число студентов, `N` — общее число результатов. Для каждого студента `student_summary` делает три прохода по его списку (среднее, минимум, максимум), всего O(N). `group_summary` один раз проходит по всем результатам для общей суммы и вызывает `find_top_students` (ещё O(N)). Итого построение статистики — O(N), дополнительная память — O(m) для итогов студентов. Рейтинг в `format_report` добавляет сортировку O(m log m).

## Итоговые выводы

**Как декомпозиция повлияла на читаемость решения.** Разбиение на небольшие функции с понятными именами позволило читать программу сверху вниз: например, `process_record` в задании 1 состоит из трёх шагов (проверить, определить уровень, составить строку), и каждый шаг — отдельная функция. Одну и ту же функцию (`linear_search`, `mean`) удалось использовать и в демонстрации, и в проверках без копирования кода. Ошибки стало проще искать: если не прошла проверка, сразу видно, в какой функции дело. А для изменения правил (например, порогов уровней или правила для пустых данных) достаточно поправить одно место.

**Выбор коллекций.**

| Задача | Коллекция | Почему |
|---|---|---|
| уникальные студенты и работы | `set` | нет повторов, быстрая проверка наличия, операции над множествами |
| попытки студента по порядку | `list` внутри `dict` | порядок важен, ключ — имя |
| результат по паре «студент, работа» | `dict` с ключом-`tuple` | поиск в среднем за O(1), кортеж хешируем |
| неизменяемый результат функции | `tuple` | нельзя случайно изменить |

**Итог по сложности:** линейные проходы — O(n), проверка простоты — O(√n), сортировка выбором — O(n²), бинарный поиск — O(log n), операции со словарями и множествами — в среднем O(1).
