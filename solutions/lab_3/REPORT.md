### Часть 1. Проверка диапазонов
Программа возвращает сообщение об ошибке или None, если данные корректны:
```
def validate(score: int, absences: int) -> str | None:
    if score < 0 or score > 100:
        return f"результат {score} вне диапазона 0–100"
    elif absences < 0 or absences > 5:
        return f"пропусков {absences} вне диапазона 0–5"
    else:
        return None
```
### Часть 2. Определение уровня результата
Определили уровень результата. Если более 3 пропусков, то уровень снижается на 1 ступень (но ниже "недостаточного" не может опускаться):
```
def get_level(score: int, absences: int) -> str:
    if score >= 90:
        index = 3
    elif score >= 75:
        index = 2
    elif score >= 60:
        index = 1
    else:  # остаются только 0–59
        index = 0

    if absences > 3 and index > 0: 
        index -= 1
    return LEVELS[index]
```
### Часть 3. Сопоставление с образцом
Сформировали пояснения для типов работы:
```
def describe_work(work_type: str) -> str:
    match work_type:
        case "exam":
            return "экзаменационная работа"
        case "project":
            return "проектная работа"
        case "practice":
            return "практическая работа"
        case _:
            return "неизвестный тип работы"
```
Программа возвращает строку результата и уровень (при ошибке уровень - None):
```
def process_record(score: int, work_type: str, absences: int) -> tuple[str, str | None]:
    error = validate(score, absences)
    if error is not None:
        return f"Ошибка: {error}", None

    level = get_level(score, absences)
    work = describe_work(work_type)
    text = f"{work}: результат {score}, пропусков {absences}, уровень — {level}"
    return text, level
```
После получения данных программа выводит тип работы, результат, количество пропусков и уровень результата:

**Порядок проверки условий:**

1. Сначала проверяются диапазоны. В `process_record` первым вызывается `validate`. Если она вернула сообщение об ошибке, функция сразу завершается через `return`: уровень не определяется и тип работы не разбирается.
2. Внутри `validate` сначала проверяется результат, затем количество пропусков. Как только сработало первое условие, остальные не проверяются, поэтому при двух ошибках сразу (сценарий 14) выводится только сообщение о результате.
3. В `get_level` пороги проверяются от большего к меньшему: `>= 90`, затем `>= 75`, затем `>= 60`, иначе - остальное. Поэтому в каждом условии достаточно записать только нижнюю границу: верхняя следует из того, что предыдущие условия не сработали.
4. Снижение уровня на ступень выполняется после определения исходного уровня: условие `absences > 3 and index > 0`. Часть `index > 0` защищает от выхода за нижнюю границу: без неё для `index = 0` получилось бы `LEVELS[-1]`, то есть «отличный».
5. В `describe_work` значение сравнивается по очереди с `exam`, `project`, `practice`, а `case _` обрабатывает всё остальное.

**Недостижимые ветви при выбранном порядке:**

- `get_level`, ветви `elif score >= 75` и `elif score >= 60` для значений 90 и выше недостижимы: такие значения уже обработала первая ветвь `score >= 90`. Аналогично `elif score >= 60` недостижима для значений 75 и выше.
- `get_level`, ветвь `else` достижима только для значений 0–59. Отрицательные значения до неё не доходят: они отсечены в `validate`, поэтому отдельной ветви для `score < 0` нет. По той же причине в `get_level` недостижимы значения выше 100.
- `validate`, ветвь `elif` недостижима при ошибочном результате: управление уходит в первую ветвь с `return`. Ветвь `else` достижима только когда обе величины корректны.
- `process_record`, код после проверки `error` (вызовы `get_level` и `describe_work`) недостижим для некорректных данных.
- `describe_work`, ветвь `case _` по условию задания при корректном вводе недостижима. Она оставлена для неизвестных значений и проверяется сценарием 11 с типом `lab`.

Если изменить порядок в `get_level` на обратный (сначала `score >= 60`), то ветви `score >= 75` и `score >= 90` стали бы недостижимыми, и любой результат от 60 получал бы уровень «удовлетворительный». Поэтому порядок от большего порога к меньшему выбран намеренно.

**Этап 1.** Первый проход (минимум и максимум начинаются с первого элемента списка):
```
def first_pass(values: list[int]) -> tuple[int, int, int, int]:
    total = 0
    minimum = values[0]
    maximum = values[0]
    even_count = 0
    for value in values:
        total += value
        if value < minimum:
            minimum = value
        if value > maximum:
            maximum = value
        if value % 2 == 0:
            even_count += 1
    return total, minimum, maximum, even_count
```

**Этап 2.** Второй проход (возвращает число элементов, строго превосходящих среднее арифметическое):

```
def count_above_average(values: list[int], average: float) -> int:
    count = 0
    for value in values:
        if value > average:
            count += 1
    return count
```

**Этап 3.** Вычисление среднего:

```
def analyze(values: list[int]) -> dict:
    total, minimum, maximum, even_count = first_pass(values)  
    average = total / len(values)
    above_average = count_above_average(values, average)
    return {
        "sum": total,
        "min": minimum,
        "max": maximum,
        "even": even_count,
        "average": average,
        "above_average": above_average,
```


### Линейный поиск первого вхождения

Функция проходит по списку слева направо и возвращает индекс первого найденного элемента и число выполненных сравнений. Если число отсутствует, возвращается индекс `-1`.

```
def linear_search(items: list[int], target: int) -> tuple[int, int]:
    comparisons = 0
    for index in range(len(items)):
        comparisons += 1
        if items[index] == target:
            return index, comparisons
    return -1, comparisons
```

### Дополнительный алгоритмический эксперимент

Делители перебираются от 2 до корня из `n` включительно. Условие `divisor * divisor <= n` равносильно `divisor <= √n`, при этом вычисления идут только в целых числах, без вещественного корня. Готовые функции проверки простоты не используются.

```
def is_prime(n: int) -> bool:
    if n < 2:
        return False
    divisor = 2
    while divisor * divisor <= n:  
        if n % divisor == 0:
            return False
        divisor += 1
    return True
```

#### Временная сложность

| Алгоритм | Временная сложность | От какого параметра зависит число операций | Дополнительная память |
|---|---|---|---|
| Первый проход `first_pass` (сумма, минимум, максимум, количество чётных) | O(n) | От длины списка `n`: каждый элемент обрабатывается ровно один раз, а внутри цикла выполняется фиксированное число действий | O(1): переменные `total`, `minimum`, `maximum`, `even_count` |
| Второй проход `count_above_average` (значения больше среднего) | O(n) | От длины списка `n`: каждый элемент сравнивается со средним один раз | O(1): переменная `count` |
| Статистика целиком `analyze` (два прохода и вычисление среднего) | O(n) + O(1) + O(n) = O(n) | От длины списка `n`: вычисление среднего — одно деление, два прохода выполняются друг за другом, а не вложенно | O(1): набор переменных обоих проходов и `average` |
| Линейный поиск `linear_search` | O(n) в худшем случае (элемент последний или отсутствует: `n` сравнений), O(1) в лучшем (элемент первый: 1 сравнение) | От длины списка `n` и позиции первого вхождения искомого числа. В списке измерений поиск числа 12 даёт 1 сравнение, а числа 100 — 10 | O(1): переменные `index` и `comparisons` |
| Проверка простоты `is_prime` | O(√n) в худшем случае (число простое или квадрат простого), O(1) в лучшем (например, чётное число отбрасывается на первом делителе) | От значения проверяемого числа `n`, а не от длины его записи: цикл перебирает делители `2, 3, 4, …`, пока `divisor * divisor <= n`, то есть не более √n значений | O(1): переменные `n` и `divisor` |

**Почему ограничение делителей квадратным корнем корректно.** Пусть `n` - составное число, то есть `n = a · b`, где `1 < a ≤ b`. Тогда `a · a ≤ a · b = n`, то есть меньший из двух делителей не превосходит √n. Значит, у любого составного числа есть делитель в диапазоне от 2 до √n, и если ни один делитель из этого диапазона не подошёл, число простое. Границу √n необходимо включать: для `n = p²` единственный нетривиальный делитель равен ровно √n. Условие `divisor * divisor <= n` включает эту границу и не требует вычисления корня в вещественных числах.

### Практическое расширение

#### Сортировка выбором

Функция сортирует список по возрастанию на месте.
```
def selection_sort(items: list[int]) -> None:
    """Сортирует список по возрастанию на месте."""
    size = len(items)
    for i in range(size - 1):
        min_index = i
        for j in range(i + 1, size):
            if items[j] < items[min_index]:
                min_index = j
        if min_index != i:
            items[i], items[min_index] = items[min_index], items[i]
```

#### Бинарный поиск

Поиск выполняется в отсортированном списке. Одно сравнение — один шаг цикла: элемент в середине сравнивается с искомым значением (равно / меньше / больше). В линейном поиске одно сравнение — одна проверка равенства элемента с искомым значением.
```
def binary_search(items: list[int], target: int) -> tuple[int, int]:
    """Ищет target в отсортированном списке.

    Возвращает (индекс или -1, число сравнений). Одно сравнение — один шаг цикла:
    элемент в середине сравнивается с искомым значением (равно / меньше / больше).
    """
    low = 0
    high = len(items) - 1
    comparisons = 0
    while low <= high:
        middle = (low + high) // 2
        comparisons += 1
        if items[middle] == target:
            return middle, comparisons
        elif items[middle] < target:
            low = middle + 1
        else:
            high = middle - 1
    return -1, comparisons
```

#### Сравнение линейного и бинарного поиска по числу сравнений

Наборы из 10, 100 и 1000 различных чисел строятся по формуле `(i * 7919 + 13) % 10007` для `i` от 0 до `n - 1`, поэтому при каждом запуске они одинаковы. Набор сортируется сортировкой выбором, после чего оба алгоритма запускаются на одном и том же отсортированном списке. Для каждого набора выполняется поиск каждого его элемента, а также поиск отсутствующего значения `-1`.
```
def make_dataset(size: int) -> list[int]:
    """Строит набор из size различных чисел (одинаковый при каждом запуске)."""
    return [(i * 7919 + 13) % 10007 for i in range(size)]


def run_comparison() -> None:
    print("\n=== Сравнение поисков по числу сравнений ===")
    search_rows = []
    for size in (10, 100, 1000):
        data = make_dataset(size)
        selection_sort(data)

        linear_total = linear_max = binary_total = binary_max = 0
        for target in data:  # ищем каждый элемент набора
            _, linear_count = linear_search(data, target)
            _, binary_count = binary_search(data, target)
            linear_total += linear_count
            binary_total += binary_count
            if linear_count > linear_max:
                linear_max = linear_count
            if binary_count > binary_max:
                binary_max = binary_count
        _, linear_miss = linear_search(data, -1)  # значения -1 в наборе нет
        _, binary_miss = binary_search(data, -1)
        search_rows.append((size, linear_total / size, linear_max, linear_miss,
                            binary_total / size, binary_max, binary_miss))

    print("Поиск (каждый элемент набора + отсутствующее значение -1):")
    print(f"{'n':>5} | {'линейный: средн.':>16} | {'макс.':>5} | {'нет':>5} | "
          f"{'бинарный: средн.':>16} | {'макс.':>5} | {'нет':>5}")
    for size, l_avg, l_max, l_miss, b_avg, b_max, b_miss in search_rows:
        print(f"{size:>5} | {l_avg:>16.1f} | {l_max:>5} | {l_miss:>5} | "
              f"{b_avg:>16.1f} | {b_max:>5} | {b_miss:>5}")
        assert l_max == size and l_miss == size
        assert b_max <= size.bit_length()
```
